# 🛒 AXS 系统材料智能决选与定稿引擎 (实施级详案)

本 SOP 旨在彻底消除材料采购环节中的“回扣猜疑”与“选品内耗”。
依托前端酷家乐的精准数据与底层的 Obsidian 供应商底价库，由 Codex 大模型充当“智能采购总监”，为客户提供最优解，并通过本地极客引擎实现极简的“购物车式”确认。

---

## 📥 阶段一：BOM 自动拆解与数据清洗 (BOM Extraction)

**目标：** 将设计图纸转化为机器可读的精确采购清单，杜绝人工漏算错算。

| 步骤节点 | 执行角色/工具 | 实施动作与系统流转 |
| :--- | :--- | :--- |
| **1. 图纸锁死** | 前端设计系统 | 触发前提：设计流 SOP（节点4）已由客户签字确认。 |
| **2. 数据导出** | 酷家乐 API | 酷家乐一键生成全案 BOM 表（包含面积、延长米、数量、规格尺寸）。 |
| **3. 智能清洗** | Antigravity + Codex | ⚡ **系统动作：** Antigravity 拦截原始 BOM 表（CSV/JSON），交由 Codex 进行数据清洗。将零散物料归类为四大项：`硬装主材`、`定制木作`、`辅材机电`、`软装家具`。 |

---

## 🧠 阶段二：AI 穿透式最优选品 (AI Optimal Matching)

**目标：** AI 代替人工跑建材市场。在满足 AXS 美学标准的前提下，自动匹配最优底价供应商。

### 1. 约束条件载入 (Loading Constraints)
*   **动作：** Codex 自动读取 Obsidian `03_进行中项目` 里的客户《需求档案》（获取总预算红线）以及设计定稿中的《美学标签》（如：微水泥、哑光、胡桃木）。

### 2. 底价库穿透检索 (Database Query)
*   **动作：** Codex 带着“清洗后的 BOM 表”与“约束条件”，进入 Obsidian `01_知识资产库/材料供应商库` 进行深度检索。
*   **AI 优选算法逻辑：**
    *   **匹配度：** 材质与颜色必须 100% 吻合前期设计的 3D 效果图。
    *   **有效性拦截：** 读取供应商条目中的“价格有效期 (Valid_Until)”字段，剔除过期报价。
    *   **最优解生成：** 在同等材质下，筛选出“供应商合作评级（星级）最高”且“出货周期匹配”的 SKU，为每个品类生成 1 个【系统极力推荐】和 1 个【备选方案】。

---

## 📱 阶段三：前端“购物车式”核定定稿 (Client Sign-off)

**实施铁律：** 客户绝不接触复杂的 Excel 表格，所有决策在本地极客引擎移动端像点外卖一样极简完成。计费逻辑必须将“物料裸价”与“AXS 系统管理费”绝对隔离展示。

### 交互节点：本地极客引擎物料决选审批流
*   **呈现方式：** Antigravity 自动将 Codex 生成的优选清单推送到本地极客引擎，生成一张【AXS 材料透明决选单】（利用本地生成的精美图文 PDF或审批单）。
*   **客户看到的界面结构：**
    *   [实景意向图] + [具体品牌 SKU] + [规格用量]
    *   **工厂裸价：** ￥12,500（明码实价，附带 Obsidian 提取的底价证明）
    *   **客户动作：** 点击“🟢 采纳系统推荐” 或 “🟡 切换备选方案”。
*   **财务透明汇总区（强制展示）：**
    *   清单全选后，底部自动汇总：`主材总计：X 元`。
    *   单列高亮显示：`AXS 项目管理服务费 (10%) = X * 0.1 元`。
*   ⚡ **系统动作 (锁单)：** 客户在手机微信端完成全部勾选并进行电子签名后，表单状态锁定为只读。

## 📦 阶段四：自动化派单与资金流转 (Dispatch & Financial Lock)

**目标：** 决策转化为物理世界的执行动作，消除主理人的下单执行工作。

| 步骤节点 | 执行角色/工具 | 实施动作与系统流转 |
| :--- | :--- | :--- |
| **1. 状态机更新** | Antigravity | 接收本地极客引擎的“已签字”回调信号。自动修改 Obsidian 档案中的材料状态为 `status: 已锁单待排产`。 |
| **2. 财务节点生成** | 系统自动生成 | 在 Obsidian 的《预算与付款透明表》中填入真实定稿数字，生成第一阶段的“主材请款单”与对应的“10% 管理费请款单”。 |
| **3. 供应商一键派单** | Antigravity + 本地极客引擎 | ⚡ **系统动作：** 按品牌自动拆分订单。系统通过本地 Python 守护进程监听机制 或邮件，自动向各个供应商发送《AXS 标准采购单》（附带尺寸图纸和交货期要求）。 |
| **4. 现场接管** | 现场执行人 | 本地极客引擎向“现场执行人”推送《材料进场验收清单》，执行人只需按系统规定的日期在工地收货即可。 |

## 🛠️ 系统配置清单 (主理人落地待办)

为了让这个材料智能定稿引擎跑通，您需要进行以下硬核配置：
- [ ] **完善 Obsidian 供应商库 (核心资产)：** 每一款常驻 SKU 必须规范化填写 YAML 属性，例：`brand: 某某瓷砖`, `color: 哑光暗红`, `price_per_sqm: 120`, `valid_until: 2026-12-31`, `contact: 张三`。
- [ ] **调教 Codex 选品 Prompt：** 编写系统级提示词，要求 Codex 严格遵循“总预算不超标”原则进行组合，如果发现基础选品已超预算，必须在系统中向主理人亮起红灯，绝不能直接推送给客户。
- [ ] **建立本地极客引擎【材料决选】审批模板：** 配置好多选组件与计算公式组件，确保 10% 的计算逻辑在前台透明可见、无法篡改。
